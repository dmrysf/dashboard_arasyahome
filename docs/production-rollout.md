# Dashboard CI, releases and production rollout

## Branches

- `main` is source.
- `deploy` is generated by GitHub Actions and contains only the verified artifact: `dist/` (with `release.json` and `dist/SHA256SUMS`), the deploy/rollback scripts, `.cpanel.yml` and a package-level `SHA256SUMS`. The server never needs Node or Vite.

## CI gates (`.github/workflows/dashboard-build-deploy.yml`)

`verified-release` publishes to `deploy` only after all of these pass:

1. `quality`: frozen install, typecheck, lint, unit tests.
2. `browser-smoke`: Chromium against the production build with an in-memory API double.
3. `real-api-e2e`: Chromium against the real Operations API on MySQL 8.4 and MariaDB 10.11. The private Operations API source is checked out read-only with the repository-scoped deploy key stored as the secret `STAFF_REPO_DEPLOY_KEY` (public half registered on `dmrysf/staff_arasyahome` as a read-only deploy key).
4. `pnpm verify` (build verification and deploy-script tests), `release.json` with the exact `main` SHA and `preview: false`, content checksums, validator with the expected SHA, and a deploy dry-run.

Repository variable `VITE_DASHBOARD_API_BASE_URL` must be `https://api.arasyahome.ro`.

## Server layout

| Path | Purpose |
|---|---|
| `$HOME/public_html/dashboard.arasyahome.ro` | Dashboard document root (the only directory the scripts write live files to) |
| `$HOME/arasya-dashboard-releases/<sha>` | Retained verified releases (mode 0750, outside `public_html`) |
| `$HOME/arasya-dashboard-releases/{active-release,previous-release,release-history.log}` | Pointers and history |
| `$HOME/repositories/dashboard_arasyahome` | cPanel Git checkout tracking `deploy` (remote `git@github-dashboard-arasyahome:dmrysf/dashboard_arasyahome.git`, read-only deploy key `~/.ssh/dashboard_arasyahome_deploy`) |

The scripts refuse any document root not named `dashboard.arasyahome.ro`, any storage inside `public_html` or the document root, and every Staff, API, config, backup, WordPress, Trendhome, OutletPerdele and Lace Secret root. `.well-known/` and `cgi-bin/` are never touched.

## Deploy

Prerequisite: Operations API 2.3.0 with migration 005 is live, `ARASYA_ALLOWED_ORIGINS` contains exactly `https://staff.arasyahome.ro` and `https://dashboard.arasyahome.ro`, Staff 2.3.0 is live, and the root identity is bootstrapped (see the Operations API `docs/central-iam.md` rollout order).

1. Confirm the latest `Dashboard Build & Publish` run on `main` is green and `deploy:dist/release.json` names that `main` SHA.
2. In cPanel Git (`dashboard_arasyahome`): **Update from Remote**, then **Deploy HEAD Commit**. Equivalent over SSH:

   ```bash
   uapi VersionControl update repository_root=$HOME/repositories/dashboard_arasyahome branch=deploy
   uapi VersionControlDeployment create repository_root=$HOME/repositories/dashboard_arasyahome
   ```

3. Check: `https://dashboard.arasyahome.ro/release.json` names the expected SHA with `preview: false`; the entrypoint has HSTS, CSP with `connect-src 'self' https://api.arasyahome.ro`, `X-Frame-Options: DENY`, `X-Robots-Tag: noindex` and `Cache-Control: no-store`; every referenced `/assets/*` file returns 200 with the immutable cache policy.

## Rollback

```bash
cd $HOME/repositories/dashboard_arasyahome
DRY_RUN=1 /bin/bash scripts/cpanel-rollback-dashboard.sh --previous   # validates and names the candidate
/bin/bash scripts/cpanel-rollback-dashboard.sh --previous              # or an explicit retained source SHA
```

Rollback re-validates every checksum and the `release.json` provenance of the retained release before switching, and records the change in `release-history.log`. The Dashboard has no database; rolling it back never affects the API or Staff.
